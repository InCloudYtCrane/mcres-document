选料审核工作台处理用户提交的帧率投稿和测评文章。入口在侧边栏「选料」下的「选料审核」，路径 `/sel/review`。

甄料师及以上能进。甄料师只能看自己审核管辖区内的稿件，掌料人及以上不受辖区限制。

# 整体布局

页面自上而下分三部分。

![](https://img.mcresource.cn/help/28_20260925_204257.jpg)

顶部是页头，左侧显示标题，右侧显示当前角色与待审总数。

接下来是标签切换，分「全部」「帧率投稿」「测评文章」三个标签。每个标签右侧带该类别下的待审数量。默认选中「全部」。

再往下是筛选栏和列表卡片。

# 帧率投稿与测评文章的区别

帧率投稿是用户提交某台硬件在某个资源上跑出来的实测帧率，包含硬件配置、实测帧率、测试场景和截图视频等。审核通过后进入选料的投稿主表，用于后续的基准计算和校准。

测评文章是用户对某个资源写的长篇评测，包含标题、摘要、正文、优缺点、适合人群、评分和测试配置等。审核通过后进入选料的测评主表，展示在资源详情页。

两类投稿的审核逻辑一致，都是通过或退回，但详情页的字段结构不同，需要关注的内容也不同。

# 列表

列表按提交时间倒序排列，每行显示以下内容。

ID 是投稿的审核表 ID。

类型标签按资源类型着色，与主站审核工作台的配色一致。

提交者显示昵称和头像。头像加载失败时降级为昵称首字母。

资源或概要一列，帧率投稿显示资源名、显卡和 CPU；测评文章显示操作类型标签、标题、资源名和摘要片段。

关键指标一列，帧率投稿显示实测平均帧率，测评文章显示主观评分。

提交时间显示到分钟。

每行末尾有「审核」按钮，与点击整行效果一致，都会打开详情页。

# 筛选

筛选栏包含资源类型下拉和搜索框。

资源类型可选全部、光影包、资源包、地图、整合包、模组。前三个是主站资源，后两个是选料的整合包和模组，来自 MC 百科映射。

搜索按资源名、标题、显卡名模糊匹配，输入即过滤。

点「重置」清空筛选条件，点「刷新」重新加载列表和统计数据。

# 分页

列表底部分页，每页 20 条。翻页时列表重新加载，页头右侧的待审总数不会变化，它反映的是当前条件下的全部待审数量。

# 帧率投稿详情

点列表中的某条帧率投稿，进入详情页。

页面顶部是投稿基本信息，包含操作类型标签、资源名与 ID、资源类型标签、当前状态、提交者昵称、提交时间。如果提交的是编辑操作，还会显示资源版本。

操作区在状态下方。待审状态下显示通过和退回两个按钮。已处理的稿件只显示一条提示文字，说明该稿件不可再操作。

实测数据区是详情页的核心，分两块。左侧是加粗放大的实测平均帧率，右侧是当时预测帧率和误差率。

误差率按颜色区分。误差率接近 1 表示预测准确，显示绿色；明显偏离 1 显示橙色或红色。这些颜色只作提示，不影响审核判定。

硬件配置区列出显卡、CPU、内存、硬盘、渲染距离。硬件信息来自用户提交时的填写，缺项显示为占位符。

测试场景区显示用户填写的测试场景描述，如果填写了。

截图区以网格形式展示用户上传的截图。点击任意截图可放大查看。截图数量多时网格自动换行。

视频区显示用户填写的 B 站视频链接，点击在新标签页打开。没有视频时这一区不显示。

# 测评文章详情

点列表中的某条测评文章，进入详情页。

页面顶部与帧率投稿类似，多了一个操作类型标签，区分新增测评和编辑已有测评。

操作区同样是待审状态显示通过和退回。

如果本次提交是编辑已有测评，页面会显示一张对比表，逐字段列出当前版本与提交版本的差异。变化的字段有浅橙背景，未变化的字段降低透明度。正文部分完整展开渲染，不做截断。

评分卡是测评文章详情页的特色区块。左侧是放大的主观评分，满分 10 分；右侧是各分维度的评分条，分维度随资源类型不同略有差异，例如光影包额外含兼容性，地图额外含关卡设计。评分理由显示在评分卡底部。

标题与摘要区显示文章标题和一句话总结。

正文区完整渲染富文本内容。正文中的图片可点击放大。

优缺点区按优点、缺点、适合谁、不适合谁四块并排展示。每块有独立的配色，优点绿、缺点红、适合蓝、不适合橙。列表项以对勾或叉号开头。

测试配置区显示测评者填写的实测硬件，字段与帧率投稿的硬件配置类似。这一区是选填的，用户没填时不显示。

利益声明区显示测评者填写的是否存在利益关系。有内容时显示为一段带蓝色左边框的说明，无内容时这一区不显示。

# 执行审核

点击通过或退回，弹出审核模态框。

通过时，附言可选。填写的内容会作为系统消息发给提交者。

退回时，附言必填。不填无法提交。附言会作为退回原因发给提交者。

模态框支持 Ctrl+Enter 快捷提交。

审核提交后，后台按以下逻辑处理。

帧率投稿通过时，把审核表的内容复制到投稿主表，同时触发一次该资源的基准校准。校准会读取该资源所有已通过的投稿和投票，算出新的校准因子并写回基准表。如果该资源已被手动锁定，校准会跳过回写并保留原值。

测评文章通过时，新增类直接写入主表，编辑类覆盖主表对应记录。测评文章不触发校准。

退回时只更新审核表状态和审核历史，不影响主表。

两种审核都会给提交者发一条系统消息，说明通过或退回，附带附言。

# 校准的触发时机

帧率投稿通过后自动触发校准，这是选料数据模型的关键机制。每次有新的合格投稿进入主表，系统会重新计算该资源的基准参数，让后续的性能预测逐步逼近真实值。

校准本身是幂等的，同一份数据多次计算不会产生漂移。因此即使同一条投稿被重复触发，也不会破坏基准。校准跳过已手动锁定的资源，避免管理员的人工调整被自动逻辑覆盖。

# 与资源基准页面的联动

审核通过触发的校准结果，会直接反映在资源基准页面。

如果你审核通过了一条帧率投稿，然后去资源基准页面查同一个资源，会看到它的校准因子发生了变化，来源标记为自动。

如果你在资源基准页面手动锁定了某个资源的校准因子，后续再审核这个资源的投稿时，校准会跳过，校准因子保持不变。

两部分配合使用，构成选料数据模型的闭环。
