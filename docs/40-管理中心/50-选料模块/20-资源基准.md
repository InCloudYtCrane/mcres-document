资源基准维护每个资源的性能预测参数，是选料数据模型的核心。每个资源的预测结果由三个值共同决定：GPU 基准帧、CPU 基准帧、模块乘数，再叠加一个校准因子微调。基准与校准因子由投稿和投票自动算出，管理员也可以手动干预。

入口在侧边栏「选料」下的「资源基准」，路径 `/sel/benchmark`。

甄料师及以上能进。甄料师只能看自己编辑管辖区内的资源，掌料人及以上不受辖区限制，且能修改基准和校准因子。

# 整体布局

页面分列表和详情两种形态。

列表页顶部是筛选栏，包含资源类型下拉、手动锁下拉、资源名搜索框，以及重置和刷新按钮。下方是基准列表表格。

点列表中的某一行进入详情页。

## 列表

列表按资源类型和资源 ID 排序，每行显示以下内容。

类型标签按资源类型着色。

资源一列显示资源名和资源 ID。

GPU 基准、CPU 基准、模块乘数、校准因子四列显示数值。校准因子偏离 1 较远时（小于 0.9 或大于 1.1）用橙色显示，正常时用白色显示。

状态列显示三种可能。手动锁表示该资源的校准因子被人工锁定，自动校准会跳过。模板兜底表示该资源没有专属基准，走的是大类模板值。自动表示有专属基准且未锁定。

# 详情页

详情页自上而下分四部分。

![](https://img.mcresource.cn/help/30_20260925_205843.jpg)

顶部是返回链接和资源头部，显示资源名、资源 ID、资源类型标签，以及如果已锁定时显示的锁定状态。

接下来是四张概览卡片，横向排列，分别显示 GPU 基准帧、CPU 基准帧、模块乘数、校准因子。

再往下是操作栏和分类模板对比。

最后是已通过投稿列表和投票列表。

## 四张概览卡片

GPU 基准帧是标准测试环境下该资源在参考显卡上的预期帧数。这个值越大，说明该资源越省性能。

CPU 基准帧是 CPU 轨道上的基准值，处理与显卡无关的负载部分。

模块乘数是整体缩放系数，用于微调整体的预测结果。

校准因子是对预测结果的比例修正。值为 1 表示不做修正，大于 1 表示实际帧数高于预测，小于 1 表示实际帧数低于预测。校准因子由系统根据真实投稿自动计算，也可以手动锁定。

四张卡片的数值取自当前资源的专属基准。专属基准不存在时，前三项显示为占位符，校准因子显示为默认值。

## 分类模板对比

如果当前资源没有专属基准，或者系统按大类模板兜底，详情页会显示一张大类模板对比卡片。

卡片列出当前资源所属类型下的通用基准帧和模块乘数。这些值是人工预设的，作为所有同类资源的起点。当某个资源的专属基准尚未建立时，系统使用模板值做预测。

模板值对所有同类型资源相同，不区分具体资源。它由料总管维护，普通管理员无法在这里修改。

## 操作栏

操作栏位于概览卡片下方，包含以下按钮。

「修改基准」用于调整 GPU 基准帧、CPU 基准帧和模块乘数。这三个值直接决定预测结果，修改后会立即影响后续预测。

「手动设校准值」用于直接指定校准因子并锁定。锁定后，自动校准会跳过该资源。适合在某个资源的真实数据不足、手动估算优于自动计算时使用。

「解除锁定」在已锁定的资源上显示，解除锁定后该资源重新参与自动校准。

「触发校准」手动触发一次该资源的校准。日常使用中不需要，因为审核通过会自动触发，但数据修复或手动干预后可以用它强制重算。

甄料师只能使用操作栏的第一个按钮，其余按钮仅在掌料人及以上显示。

## 修改基准

点「修改基准」打开模态框，包含三个输入框。

GPU 基准帧的有效范围是 0 到 100000，可以有小数。

CPU 基准帧的有效范围同上。

模块乘数的有效范围是 0.01 到 100，可以有三位小数。

保存时后台会校验数值范围。超出范围时拒绝提交并给出提示。

若该资源尚无专属基准，保存会创建一条新记录，来源标记为人工，校准因子初始为 1.0。若已有专属基准，则更新对应字段。

修改基准不会影响校准因子。校准因子仍由自动逻辑或手动设置独立管理。

## 手动设校准值

点「手动设校准值」打开模态框，只有一个输入框用于填写校准因子。

有效范围是 0.01 到 10。常用范围是 0.5 到 2.0，1.0 表示不做修正。

保存后校准因子立即更新，同时 `is_manual` 标记置为 1，表示该资源已被手动锁定。

手动锁定不影响基准帧和模块乘数，只是让自动校准不再覆盖校准因子。

## 解除锁定

点「解除锁定」，二次确认后把 `is_manual` 置为 0。

解除锁定后，该资源重新参与自动校准。下次有投稿通过或手动触发校准，校准因子会被重新计算并覆盖当前值。

解除锁定不影响校准因子的当前值，只是在下次校准时不再跳过。

## 触发校准

点「触发校准」打开一次确认，确认后向选料模块发起校准请求。

校准过程读取该资源所有已通过的投稿和投票，按统计方法计算新的校准因子，写回基准表。如果该资源已被手动锁定，校准会返回跳过状态并保留原值。

校准完成后，页面提示本次校准的结果，包含新的校准因子和参与计算的样本数，随后自动刷新详情页。

## 已通过投稿列表

详情页下半部分是已通过投稿列表，显示该资源所有审核通过的帧率投稿。

表格每行包含投稿 ID、提交者昵称、实测帧率、当时预测帧率、误差率和提交时间。

误差率按颜色区分。误差率接近 1 显示绿色，偏离明显显示橙色或红色。误差率是审核质量和资源基准质量的综合反映，长期偏离说明预测模型需要调整。

列表最多显示 200 条，按提交时间倒序。

## 投票列表

详情页最下方是投票列表，显示该资源收到的所有用户投票。

表格每行包含投票 ID、用户 ID 或匿名、反馈类型、权重和投票时间。

反馈类型有三种：偏大、准确、偏小。这是用户对预测结果的定性评价，用于辅助校准。

权重是投票对校准的影响系数。用户信誉分越高，权重越大。

匿名投票不显示用户 ID，只显示为匿名。

投票列表最多显示 200 条，按投票时间倒序。

## 校准的统计逻辑

校准因子由投稿和投票共同决定。系统的处理流程如下。

先把所有已通过的投稿按硬件配置映射到 GPU 轨道和 CPU 轨道，算出每条投稿的等效分数。

然后按时间衰减给每条投稿加权。越近的投稿权重越高，旧投稿的权重逐步降低。

再把用户投票作为软约束叠加进去。反馈为「准确」的投票对校准因子的调整方向没有偏向，「偏大」和「偏小」分别向两个方向施加影响，影响幅度由权重决定。

最后用贝叶斯收缩方法把结果向 1.0 收缩。样本数少时，校准因子接近 1.0；样本数增多，校准因子才逐步放开到实际值。

整个计算过程是确定性的，同样的输入得到同样的输出。因此校准可以反复触发而不产生漂移。

# 校准因子的合理区间

校准因子通常在 0.5 到 2.0 之间。超出这个范围说明预测模型和实际数据存在系统性偏差，需要人工核查。

常见的原因有几类。资源本身发生了版本更新，性能特征改变但基准帧未同步更新。投稿数据存在大量异常值，例如个别用户在极端硬件配置下的成绩拉偏了均值。硬件库里的某个型号被错误标记了分数，导致映射结果失真。

遇到校准因子明显异常时，建议先看已通过投稿列表和投票列表，找出可疑的投稿或硬件。必要时在硬件库里修正对应型号，然后重新触发校准。

# 与选料审核的联动

选料审核工作台审核通过一条帧率投稿后，系统会自动触发该资源的校准。因此正常情况下，管理员不需要手动触发校准。

需要手动触发校准的场景包括：批量修正了硬件库里的某个型号后，希望所有受影响资源立即重算；核查某条投稿或投票是否被正确计入；修复了投稿表的数据异常后重新生成校准结果。

# 与主站性能预测的关系

资源基准的最终用途是支撑主站的性能预测功能。用户在资源详情页输入自己的硬件配置，系统按该资源的基准帧、模块乘数和校准因子算出预期帧率。

因此资源基准的质量直接影响主站性能预测的准确性。管理员在修改基准或校准因子时，需要清楚改动会影响所有使用该预测的用户。

预测过程不涉及选料审核表，只读取基准表、硬件库和用户的硬件输入，因此基准表的每次修改都会立即生效，无需额外操作。
