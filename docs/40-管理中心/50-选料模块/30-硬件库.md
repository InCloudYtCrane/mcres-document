硬件库维护显卡和 CPU 的型号与性能分数，是选料性能预测的硬件基础。用户提交帧率投稿时填写的硬件名称，会映射到硬件库里的具体型号，取该型号的分数参与基准计算。

入口在侧边栏「选料」下的「硬件库」，路径 `/sel/hardware`。

掌料人及以上能进入并做单条增删改。料总管额外能批量导入和批量删除。

# 整体布局

![](https://img.mcresource.cn/help/31_20260925_210742.jpg)

页面顶部是页头，显示当前角色与操作范围提示。

页头下方是显卡和 CPU 两个标签，每个标签右侧带该类别下的型号数量。默认选中显卡。

再往下是筛选栏和列表卡片。

列表底部是批量操作栏，仅在料总管角色下勾选型号后出现。

# 显卡与 CPU 的字段差异

两个类别共用一套列表和操作流程，但字段不同。

显卡包含名称、档位、Time Spy 分数、显存、归算系数五个字段。

CPU 包含名称、档位、R23 单核分、R23 多核分四个字段。

档位是自由文本，用于分类展示和人工参考，不参与计算。常见取值有「入门」「主流」「高端」「旗舰」等。

Time Spy 分数来自 3DMark 的显卡基准测试，反映显卡在标准负载下的综合性能。

显存是自由文本，允许填写「8GB」「32GB GDDR7」这类描述性内容，不参与计算。

归算系数是显卡分数的微调系数，默认 1.0。它把不同测试方式下的分数归一化到同一量纲。多数情况下保持默认即可，只有某个型号的分数来源不一致时才需要调整。

R23 单核分和 R23 多核分来自 Cinebench R23，分别反映 CPU 的单核性能和多核性能。

# 列表

列表按分数从高到低排序，显卡按 Time Spy 分数排，CPU 按 R23 单核分排。因此高性能型号出现在列表顶部。

每行显示该类型的全部字段，加上 ID 和操作按钮。

操作按钮包含「编辑」和「删除」。

料总管角色下每行左侧还有一个多选框，用于批量操作。

# 筛选

筛选栏只有一个搜索框，按型号名称模糊匹配。

输入即过滤，切换标签时搜索条件清空。

点「重置」清空搜索框并重新加载，点「刷新」在当前条件下重新拉取数据。

# 新增型号

点筛选栏右侧的「新增型号」按钮，打开编辑模态框。

模态框根据当前标签自动切换字段。显卡标签下显示显卡字段，CPU 标签下显示 CPU 字段。

各字段的校验规则如下。

名称必填，最多 100 字。

档位可选，最多 20 字。

显卡的 Time Spy 分数必填，范围 0 到 100000。

显卡的显存可选，最多 20 字。

显卡的归算系数可选，范围 0.01 到 100，留空时默认为 1.0。

CPU 的 R23 单核分必填，范围 0 到 10000。

CPU 的 R23 多核分必填，范围 0 到 100000。

名称为空、分数超出范围、格式不合法时，模态框内显示对应提示，不提交请求。

保存时后台会检查型号名是否已存在。重名时拒绝创建并提示。同名不同规格的型号需要手动区分，例如加后缀或备注。

# 编辑型号

点列表中的「编辑」按钮打开模态框，加载该型号的当前值。

可修改的字段与新增一致，名称也可以改。保存时同样会检查重名，排除自身。

编辑成功后列表刷新。

# 删除型号

点列表中的「删除」按钮，二次确认后删除。

单个删除不需要批量权限，掌料人即可操作。

删除一个正在被投稿引用的型号会导致投稿的硬件映射失败。因此删除前应确认该型号没有被已通过的投稿使用。系统不做引用检查，删除操作是无条件的。

# 批量操作

料总管角色下，列表左侧每行有多选框。勾选型号后，列表底部出现批量操作栏，显示已选数量，提供「批量删除」和「取消选择」。

批量删除最多一次处理 100 条。

若勾选的型号中存在被投稿引用的，批量删除会一并执行。因此批量删除前应导出或核对一遍当前列表，确认没有正在使用的型号。

# 批量导入

料总管可以通过 JSON 或 CSV 文件批量导入型号。

点筛选栏右侧的「批量导入」按钮，打开导入模态框。

## 导入格式

模态框顶部有 JSON 和 CSV 两个标签，切换导入格式。

JSON 格式要求顶层是一个数组，每个元素是一个对象，字段名与型号字段对应。

显卡的 JSON 示例为一个包含 `name`、`tier`、`ts_score`、`vram`、`conversion_factor` 的数组。

CPU 的 JSON 示例为一个包含 `name`、`tier`、`r23_single`、`r23_multi` 的数组。

CSV 格式要求首行是表头。显卡的表头为 `name,tier,ts_score,vram,conversion_factor`，CPU 的表头为 `name,tier,r23_single,r23_multi`。

## 数据来源

可以直接把内容粘贴到文本域里，也可以通过「选择文件」按钮选择本地的 JSON 或 CSV 文件。

选择文件后，文件内容会自动读入文本域，可以继续编辑。

JSON示例：

```JSON
{
    "name": "RTX 4060", 
    "tier": "主流", 
    "ts_score": 10000, 
    "vram": "8GB", 
    "conversion_factor": 1.0
}
```

## 导入结果

点「开始导入」后，后台逐条解析、校验并写入。

每个元素分别处理。校验失败、字段缺失、数值超范围的记入失败；名称已存在的记入跳过；其余写入数据库，计入成功。

导入完成后，模态框内显示三类结果的统计，包含成功数、跳过数、失败数。跳过和失败的明细以折叠列表展示，每项包含原始行号和失败原因。

导入过程不做事务回滚，即部分成功部分失败的情况下，成功的记录会保留。

## 导入的常见问题

跳过的原因基本都是重名。若希望覆盖已有型号，需要先删除再导入。

失败的原因以数值超范围和格式错误为主。例如 Time Spy 分数写成了非数字，或者 R23 单核分超出 10000。

CSV 文件里如果包含逗号或换行，需要用双引号包裹。否则解析会出错。

# 硬件库与选料审核的关系

用户提交帧率投稿时，会从硬件库里选择显卡和 CPU 型号。系统按所选型号的分数参与基准计算。

如果用户提交的硬件型号不在硬件库里，投稿的硬件映射会失败，导致这条投稿无法参与校准。因此当出现「某条合格投稿未被计入校准」的情况时，先检查该投稿使用的硬件型号是否已经在硬件库里。

补录型号后，重新触发对应资源的校准即可让这条投稿参与计算。
