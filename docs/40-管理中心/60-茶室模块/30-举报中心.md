举报中心用来处理茶室用户提交的举报，包括帖子、回复、用户三类目标的举报。入口在侧边栏「茶室」下的「举报中心」，路径 `/tea/report`。

茶博士及以上能进入。

# 整体布局

页面顶部是页头，显示举报总数。

下方是状态标签页，包含待处理、已处理、已驳回、全部四个标签。

再往下是批量操作栏，仅在待处理标签下显示。

最下方是举报列表表格，包含分页。

# 状态标签

待处理是默认标签，显示所有未处理的举报。这是日常处理的主要入口。

已处理显示已经确认成立的举报。

已驳回显示被判定为不成立或被驳回的举报。

全部显示所有状态的举报。

# 举报列表

列表按举报时间倒序排列，每行显示以下内容。

第一列是多选框，仅在待处理标签下显示。

ID 是举报记录的主键。

举报人一列显示提交举报的用户昵称和 ID。

类型显示被举报目标的类别，分为帖子、回复、用户三种。

被举报内容一列显示举报目标的摘要。帖子显示标题，回复显示内容摘要，用户显示昵称。如果举报详情较长，标题右侧会出现「详情」按钮，点击展开该条举报的完整详情。

举报目标可点击跳转到对应的主站页面。回复类举报会跳到该回复所在帖子的对应锚点。用户类举报会跳到该用户的茶室主页。

理由一列显示用户提交举报时选择的类别，包括垃圾广告、骚扰攻击、色情低俗、违法违规、无关内容、其他。

时间显示举报的提交时间。

状态显示当前处理状态。

操作一列在待处理标签下显示「驳回」和「已处理」两个按钮。其他标签下不显示操作。

# 处理举报

在待处理标签下，每条举报可以执行两种处理。

「已处理」表示举报成立，记录下处理结果。一般是确认内容违规，随后由管理员手动对目标执行处罚。

「驳回」表示举报不成立，同样记录下结果。

处理时会记录处理人和处理时间。处理后该举报从待处理列表移到对应的状态列表。

# 批量处理

在待处理标签下勾选多条举报后，批量操作栏激活，提供「批量已处理」和「批量驳回」两个按钮。

执行前会二次确认，显示本次要处理的举报数量。

批量操作不检查举报详情，只是统一更新状态。因此执行前建议先逐条核对，或至少随机抽查几条。

# 举报详情

举报详情来自用户提交时的补充说明字段。不是所有举报都有详情，有详情的举报会显示「详情」按钮。

点「详情」按钮展开该条举报的完整内容，再点一次收起。

详情展示在举报行的下一行，占据整行的宽度，内容以普通文本形式呈现。

# 与用户处罚的关系

举报中心只负责处理举报的状态，不直接执行用户处罚。

若某条举报成立且需要处罚，处理完举报后，去批量处罚页面执行对应的处罚，或者在用户处罚记录里核对已有处罚。

举报处理与处罚是两套独立的操作，互不影响。举报中心不记录处罚信息，处罚记录里也不显示关联的举报 ID。

# 分页

列表底部分页，每页 30 条。

翻页时状态标签保留，只有页码变化。
