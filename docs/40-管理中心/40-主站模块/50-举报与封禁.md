举报与封禁是处理用户举报和账户处罚的页面。用户在主站举报评论或用户后，记录会汇总到这里，管理员查看举报详情，决定忽略还是封禁目标用户。同时这个页面也提供对所有用户的封禁管理入口。

入口在侧边栏「举报与封禁」，路径 `/3_ban`。

精英工匠及以上能进入。精英工匠可以处理举报和执行封禁，但封禁目标受角色层级限制，详见后面的章节。

# 整体布局

![](https://img.mcresource.cn/help/19_20260925_185431.jpg)

页面自上而下分三部分。

顶部是统计卡片，显示总用户数，以及当前处于编辑封禁、评论封禁、登录封禁状态的用户数量。

中部是待处理举报区，列出所有未处理的举报记录。

下部是用户列表，包含全部用户，提供搜索和角色筛选，每行末尾有「管理封禁」按钮。

# 举报列表

举报列表按举报时间倒序排列，每条记录显示举报人、被举报人、被举报内容摘要、举报理由、举报时间和处理按钮。

被举报内容按目标类型显示。目标为帖子时显示帖子标题；目标为回复时显示回复内容摘要，超过一定长度截断；目标为用户时显示目标用户昵称。

举报理由来自用户举报时选择的类别，包括垃圾广告、骚扰攻击、色情低俗、违法违规、无关内容、其他六项。

没有待处理举报时，举报区显示「暂无待处理的举报」。

# 处理举报

点击某条举报的「处理」按钮，弹出详情模态框。

模态框顶部显示被举报人的头像、昵称、用户 ID，以及举报人昵称。

接下来依次列出被举报评论的完整内容、举报理由、举报人和举报时间。

底部有两个操作按钮。

「忽略/已处理」把这条举报标记为已处理，不再出现在待处理列表中。适用于举报不成立或已通过其他方式处理的情况。

「封禁该用户」先关闭举报详情，再打开封禁管理模态框，并把举报理由自动填入封禁理由字段，方便直接执行处罚。

处理完成后，该条举报从列表移除，顶部举报数量同步减少。若全部处理完，列表区显示空状态。

举报详情模态框点空白或按 ESC 关闭，不会执行任何操作。

# 用户列表

用户列表包含全部用户，按 ID 升序排列。

每行显示用户 ID、头像、昵称、当前角色，以及编辑、评论、登录三项封禁状态。封禁状态下，如果是封禁中，会显示封禁理由、截止时间和操作员。如果未封禁，显示绿色的「正常」。

搜索框按昵称或用户 ID 模糊匹配，即时生效。

角色筛选项包含全部角色和五个具体角色。

「重置」按钮清空搜索和筛选条件。

# 封禁管理

点击用户行的「管理封禁」按钮，弹出封禁管理模态框。

![](https://img.mcresource.cn/help/20_20260925_185402.jpg)

模态框顶部显示目标用户的头像、昵称和角色信息。

接下来是三栏封禁状态，分别对应编辑、评论、登录三种封禁类型。每栏显示该类型的当前状态。封禁中显示理由、截止时间和操作员；未封禁显示为正常。

下部是操作表单，包含三个字段。

封禁类型选择本次操作的封禁类型：编辑、评论、登录。

截止时间是封禁的到期时间。到点后系统自动解除。这个字段只在执行封禁时使用。

理由是封禁原因，会在用户被拦截时显示给用户。可选。

表单底部有三个按钮。

「取消」关闭模态框不执行操作。

「解除」清除所选封禁类型的封禁。执行前会二次确认，完成后给用户发一条解封的系统消息。

「封禁」对所选类型设置封禁，按截止时间和理由生效。执行前会二次确认，完成后给用户发一条封禁的系统消息。

# 封禁的三种类型

编辑封禁限制用户在资源提交、编辑等需要写操作的场景。被拦截时用户看到提示，说明封禁类型、理由和解封时间。

评论封禁限制用户在主站发表评论、回复、表态等互动。

登录封禁限制用户登录主站。已登录的用户在下次会话过期后无法重新登录。

三种封禁相互独立，可以只封其中一种，也可以同时封多种。

# 用户被拦截时的表现

用户在被封禁类型对应的操作里触发拦截时，会跳转到一个专门的错误页。

错误页显示处罚等级图标和对应的处罚名称，说明本次操作被拦截的原因，列出触发词，如果举报处理中有关联词，还会给出对应的信誉分扣减说明。

页面会自动倒计时若干秒后跳回用户原来的页面，用户可以手动点「立即返回」提前跳回。

# 角色层级与封禁权限

精英工匠和工坊主管都能执行封禁，但都受角色层级限制。

精英工匠不能封禁角色级别不低于自己的用户，也就是不能封禁精英工匠和工坊主管。

工坊主管不能封禁自己，也不能封禁同级或更高级别的用户。

任何管理员都不能对自己执行封禁。

目标用户不存在、参数缺失、未登录等情况下，操作会被拒绝并给出对应提示。

# 自动解封

用户列表加载时，后台会遍历每个用户的封禁数据，把截止时间早于当前时间的封禁记录自动清除。

这一过程在页面加载时进行，不影响其他用户的封禁状态。清除后，用户列表上的封禁状态同步刷新。

因此即使没有管理员手动解封，到期的封禁也会在用户下次被封禁相关操作拦截时被识别为已失效。但为了给用户及时解封，建议管理员在处理举报或核查用户时顺手看一眼有没有到期的记录。

# 举报处理的系统消息

无论执行忽略还是封禁，系统都会给目标用户发一条消息。封禁消息说明封禁类型、理由和截止时间，同时附上操作员昵称和 ID，方便用户申诉。

解封时同样会发一条消息，说明解封的类型和解封时间。

这些消息记录在用户的站内消息中，可在主站消息中心查看。
